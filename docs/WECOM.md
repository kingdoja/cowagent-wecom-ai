# 企业微信接入决策与执行清单

## 1. 结论

当前项目可以接入企业微信。第一阶段采用 CowAgent 原生的 **企微智能机器人（WeCom Bot）WebSocket 长连接**，并保留现有 Web 控制台。

不优先采用企微自建应用或 HTTP 回调，原因是当前服务运行在本机 Docker 和 Tailscale 私网中。长连接由本机主动连接企业微信，不需要公网 IP、备案域名、入站端口或反向代理，风险和运维成本都更低。

## 2. 方案比较

| 方案 | 适用对象 | 群聊 | 公网入口 | 当前建议 |
| --- | --- | --- | --- | --- |
| 企微智能机器人长连接 | 企业内部单聊、群聊 `@` | 支持 | 不需要 | 第一阶段采用 |
| 企微自建应用 | 需要企业应用可见范围和应用治理 | 主要是单聊 | 需要 | 有明确合规需求再做 |
| 微信客服 | 外部联系人或客户服务 | 不适用 | 通常需要 | 独立项目评估 |
| 群机器人 Webhook | 单向通知或简单命令 | 支持有限 | 取决于实现 | 不作为 AI 对话主入口 |

CowAgent 当前镜像中的企微智能机器人支持文本、图片、文件、流式回复和定时任务主动推送。首期仍只开放普通聊天，Agent 工具与自进化保持关闭。

本部署通过 `runtime/cowagent_streaming_patch.py` 将普通 OpenAI 兼容聊天切换为 SSE 流式调用，使企微在首个文本 token 到达后开始更新回复。设置 `COW_STREAMING_PATCH_ENABLED=False` 并执行 `make up` 可立即回滚到上游非流式行为。

流式输出只能缩短“首个 token 到达后”的体感等待，无法解决模型或中转站迟迟不返回首个 token。使用 `make test-streaming` 可分别观察 `first_token` 和 `total`；若两者都很高，应更换模型或中转线路，而不是继续调整企微通道。

## 3. 接入架构

```text
企业微信员工 / 内部群
          |
          | WebSocket 长连接
          v
CowAgent WeCom Bot + Web 控制台
          |
          | OpenAI-compatible Chat Completions
          v
      模型中转站
```

信任边界：

- 企业微信负责员工身份、机器人可见范围和群成员管理。
- CowAgent 负责消息上下文、模型调用和通道连接。
- Tailscale 仅用于访问 Web 管理端，不承载企微消息回调。
- 企微 Secret、模型子密钥和 Web 密码必须相互独立并可单独轮换。

## 4. 分阶段执行

### 阶段 0：上线前置

- [ ] 中转站 Chat Completions 稳定性通过。当前已验证可返回正常文本，但也捕获到成功响应正文为空。
- [x] CowAgent Web 容器可运行。
- [x] Agent 与自进化默认关闭。
- [x] Web 端只绑定 Tailscale 私网地址。
- [x] 增加启动日志敏感值脱敏和 Docker 日志轮转。
- [ ] 轮换当前模型子密钥和 Web 密码。修复前的容器日志曾记录原值，旧值不应继续用于正式环境。
- [ ] 确认 `data/cow` 的私密备份和访问权限。
- [ ] 测试通过后锁定 CowAgent 镜像 digest，不长期使用 `latest`。

### 阶段 1：扫码接入

1. 在本机打开 `http://127.0.0.1:19999`；手机也可通过 Tailscale 地址打开 Web 控制台。
2. 进入 **Channels / 通道**，点击 **接入通道**。
3. 选择 **企微智能机器人**，保留 **扫码接入**。
4. 点击 **扫码创建企微机器人**，用企业微信扫码并授权。
5. 在企业微信工作台的 **智能机器人** 中设置名称、头像和最小可见范围。
6. 执行 `make wecom-status`，预期输出 `WeCom Bot is connected.`。

扫码流程会把 Bot ID 与 Secret 保存到 CowAgent 数据目录，不需要把它们写入仓库或 `.env`。

### 阶段 2：功能验收

- [ ] 机器人单聊连续问答正常。
- [ ] 内部群添加机器人后，仅在 `@机器人` 时回复。
- [ ] 中文长回答与 Markdown 显示正常。
- [ ] 图片收发按实际需求验证。
- [ ] 文件收发按实际需求验证，敏感文件不得自动转存到外部模型。
- [ ] 容器重启后机器人自动重连。
- [ ] 无权限员工不可见或不可使用机器人。
- [ ] 模型超时、限流或失败时给出可理解的错误，不重复发送消息。
- [ ] 连续执行至少十次 `make test-relay` 均返回非空文本。

### 阶段 3：小范围试运行

- 先将可见范围限制为维护者和少量测试成员。
- 观察三到七天的稳定性、模型费用、敏感信息和群聊误触发。
- 通过后再扩大部门范围；Codex、Shell、Git 和 MCP 等工具继续保持关闭。

## 5. 安全与治理

- 不在群聊、截图、工单或普通日志中粘贴 Secret。
- 当前部署已在 Python 日志入口统一隐藏环境覆盖值，并限制 Docker 日志大小；正式使用前仍应轮换修复前已记录过的值，并限制 Docker 日志读取权限。
- 机器人初始可见范围采用最小权限，群聊只响应明确 `@`。
- 不把企业微信身份直接等同于代码仓库写权限。未来 Codex Bridge 必须另做用户映射、仓库白名单和人工审批。
- 若对聊天内容有数据出境、留存或审计要求，应先确认模型中转站的数据处理条款，再扩大使用范围。

## 6. 回滚

在 Web 控制台的 Channels 页面断开企微智能机器人，并在企业微信工作台中停用或删除机器人。随后撤销 Bot Secret；Web 控制台与模型链路可继续独立运行。
